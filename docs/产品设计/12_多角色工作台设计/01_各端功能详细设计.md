# 各端功能详细设计：以 HR 工作台为中心协作

日期：2026-10-03。状态：本轮设计稿；只定义功能和实施验收，不表示页面、数据库迁移或外部集成已经完成。

本方案的“端”是同一系统内的工作视图：招聘 HR、招聘负责人、系统管理员三个常驻后台视图，以及面试官、用人负责人的事项视图。共用账号、对象、待办和业务接口；不建设五份候选人库或五套可独立推进的招聘流程。候选人基础确认／改期仍是 F16 首版链路，必须有真实的本人受限入口；完整候选人 App 与 HR 手机端沿原分期，本轮不展开。

## 1. 使用约定与现状

- 功能编号 H/L/A/I/B 便于本轮阅读，继续复用旧规格 F 编号：详细共用动作见 [05 功能规格](../05_UI与功能颗粒度规格.md)，既有实体见 [06 数据字典](../06_数据库字典与实体关系.md)，接口与状态见 [07 接口状态](../07_接口状态与开发验收.md)。本方案不复制另一套同义接口。
- 岗位画像遵循 [10 人才画像方案](../10_人才画像设计与闭环方案.md) 与 [11 飞书对照方案](../11_飞书职位画像对照与人才画像闭环设计.md)：**有职位经办权限的 HR 保存并使用，无需用人负责人另行审批**。旧 F06/F07/F25/F39 中要求他人批准画像的文字按此替代；编制、面后业务决定和 Offer 审批仍是不同事项。
- 企业 HR 已在使用飞书招聘及飞书招聘助手。插件向飞书采集；本项目不假设已经接通招聘数据接口。每条应聘只有一个阶段事实来源。飞书管理的应聘在本系统只做获授权分析或只读投影；需要动作时到飞书处理，或在真实写入并回读后更新外部状态。
- 本地经办流程仅作用于明确由本系统管理的应聘。手动导入外部材料作分析不得悄悄创建可推进的本地应聘。网页、飞书卡片和消息若引用同一事项，必须处理同一业务记录。
- 当前代码提供 `DepartmentRole` 的 `hr / supervisor / manager / interviewer` 及独立简历下载能力；尚无完整组织级业务管理员授权。`can_edit` 要求 HR 部门身份且为职位负责人或协作者，主管只读范围不能直接转换为经办权。
- 下文“已有代码线索”仅表示 2026-10-03 核查时发现相应模型／模块，不代替运行和验收。当前工作区存在并行改动；实施前须再检查最新提交、迁移及测试。既有规格中的早期“只有占位页”记录不可当作当前实现状态。

### 所有功能共用规则

F01 登录与身份、F03 搜索与消息、F20 提醒、F24 操作留痕、F42 下载与治理不因分端另建一套。每次读取、写入、搜索、统计、下载和 AI 输入都检查“当前组织＋动作能力＋对象范围＋字段权限”。兼任角色只切工作视图；不能拼接一个角色的动作与另一个角色的最大范围。

所有业务动作带对象版本；重复提交返回原结果，冲突保留输入并提示最新状态。任务完成由来源业务动作驱动，消息已读不等于任务完成。等待模型不长时间锁住业务对象，返回时重查权限与输入版本。部分失败逐项显示，未知外部结果先核对再重试。AI 输出只作草稿或参考，不能自动淘汰、录用或改变岗位标准。

## 2. 招聘 HR 工作台

### H01 今天与待办｜F02/F03/F20

- **目标与入口：** 登录默认进入“今天”；上方需要我处理，下方等待他人，旁边今日日程。点击任务回到同一职位、应聘、面试或澄清事项。
- **对象与字段：** `Task` 的类型、对象、责任人、期限、状态；显示职位／人选、处理原因、最后变化、主要动作。等待他人列明在等谁，不能算作“待我决定”。
- **前提与权限：** 成员有效且可处理／读取来源对象；仅收到任务或通知不能取得全部档案权限。管理员异常任务与 HR 招聘任务分别投影。
- **主要动作：** 处理、查看最新状态、按已启用规则提醒；有协调权限时转交并写原因。稍后提醒只调整提醒计划，不能勾掉尚未完成的业务。
- **写入与结果：** 复用来源记录及其 `Task`；处理成功同事务结束旧待办、生成下一责任人的待办。日程读取真实 `Interview`，不以任务已建代替约面成功。
- **交给谁：** 补资料交经办 HR，面评交本场面试官，业务决定交被指定负责人；HR 看见等待状态和到期时间。
- **异常与并发：** 他人已处理时显示结果；被撤权只留最小提示；源对象终结后取消失效待办和未发送提醒，旧通知不能复活任务。
- **验收／代码线索：** 数字与下钻条数一致，同一事项网页处理后不再待办。已有 `Task`、`views.dashboard`、`workspace.tsx`；完整消息／催办链按 F03/F20 补齐。

### H02 职位、JD 与岗位画像｜F04–F08

- **目标与入口：** “职位→详情→招人要求”；现有“人才画像”入口打开相同 `Job.active_profile`，不再维护另一套要求。
- **对象与字段：** 职位、企业、部门、地点、负责人、人数、JD；画像含工作经历、教育经历、技能／项目、必须／加分／排除偏好、依据、来源、待核实项及版本。
- **前提与权限：** 当前部门 HR 且具备职位经办权；企业只可选同组织有效对象。岗位标准、必要编制审批、对外广告发布分别验证，不互相代替。
- **主要动作：** 建岗／复制；编辑 JD；AI 起草并逐条采用；保存草稿；向指定业务人澄清；HR 检查后“保存并使用”；暂停／关闭前查看在途事项与渠道影响。
- **写入与结果：** 复用 `Job / JobMember / ProfileVersion / ProfileRequirement / ProfileGeneration / ProfileClarification`。启用固定正式版本与操作者，更新 active_profile 并留审计；未核实必须项阻止生效。
- **交给谁：** 生效画像供 H04/H05/H06 使用；澄清问题交 B01，答复只回给 HR 整理；对外发岗仍由获授权 HR 在实际流程主系统完成。
- **异常与并发：** AI 失败可手填；新稿不覆盖生效版；旧版本到达的 AI 结果提示过期。复制不复制应聘、生效状态或渠道编号；新标准不改旧人工决定。
- **验收／代码线索：** 两入口显示相同版本，HR 无需他人审批即可使用有效标准。已有岗位、画像、AI 草稿与澄清代码；画像标签增强、渠道实际发布及完整匹配按相应切片验收。

### H03 候选人导入、主档与应聘｜F09–F11/F13

- **目标与入口：** “候选人→当前应聘／人才档案”；导入第一步说明用途：“本系统管理应聘”或“外部材料仅作分析”，不能在同一确认按钮下产生不同隐含结果。
- **对象与字段：** 人选身份信息、资料来源与时间、文件／解析版本、目标职位、应聘次数、经办人、当前阶段、流程主系统。未知联系方式明确待补齐，不填虚构占位号码。
- **前提与权限：** 本地加入职位同时要求来源材料使用权和目标职位经办权；外部材料仅作分析要求来源使用权，以及所选参考岗位的读取权，不强制建岗或新建应聘，也不扩大材料范围。跨部门读取不等于允许共享到目标岗位；下载独立授权。
- **主要动作：** 上传与逐项解析；核对身份／疑似重复；确认新建或复用主档；选择本次材料并加入职位；补充材料；按证据人工通过、待补充或暂不推进。
- **写入与结果：** 复用 `ImportBatch / ImportItem / ResumeDocument / ResumeParse / Candidate / Application / ApplicationEntry / ApplicationResume`；复核写 `ReviewDecision / StageEvent / Task`。同人同岗仅一条活跃应聘。
- **交给谁：** 解析缺项交导入 HR，身份冲突交有权限的核对人；本地应聘进入 H04/H06；外部参考材料只进入 H04 分析，阶段仍交原系统 HR。
- **异常与并发：** 一批部分成功不回滚全部；同名不自动合并；重复确认不重建应聘。合档前预览引用、权限和活跃应聘冲突，不能承诺任意时刻无损撤销。
- **验收／代码线索：** 同一人两个职位的人才数为 1、应聘数为 2，各自材料和阶段不串。已有 `intake.py` 及主档／应聘／解析模型；跨来源合档、独立分库和外部只分析入口需单独验收。

### H04 AI 初面参考与正式岗位匹配｜F12/F13/F14，兼容现有 AI 初面切片

- **目标与入口：** 保留当前“AI 初面”作为 HR 分析与核实工具；从应聘详情打开时带入本次应聘、岗位、材料和标准。它不表示系统已经与候选人进行自主语音／视频面试。
- **对象与字段：** 本次输入、岗位画像版本、简历解析版本、企业背书快照、报告版本、原文引用、待核实问题、核实答复及来源。未绑应聘的手动材料明确标“参考分析”。
- **前提与权限：** 只读取本人获授权材料；选定应聘时职位必须一致。正式匹配另要求本次材料绑定及有效画像，不用企业宣传补造人选能力。
- **主要动作：** 预览输入→生成报告→查看引用与缺口→记录核实／待补充→选择通用问题入题库，或将个体问题带入本场提纲。正式评估完成后 HR 再人工复核。
- **写入与结果：** 参考分析复用 `AIScreening / AIScreeningVerification`；正式岗位评估沿用拟定 `Evaluation / EvaluationInput / EvaluationItem`，记录确切输入与逐项结果；人工推进另写 `ReviewDecision`。
- **交给谁：** 待核实项交经办 HR 或获授权面试官；通用题交 H08，个体追问交 H06/I02。未经人工采用不进入共享题库或已确认能力证据。
- **异常与并发：** 引用不存在标待核验；信息不足不等于不满足。模型失败保留上次成功结果；输入变化标过期，不覆盖旧报告。评分标尺未定不伪造总分或星级。
- **验收／代码线索：** 当前 `AIScreening` 已有 `profile / resume_parse / source_context`，并校验应聘与职位一致；核实记录已有修订模型。但这些仍不等于正式 `Evaluation`、已提交面评或招聘决定；旧报告缺来源不得补造。

### H05 人才库与按岗推荐｜F11/F12，参见 11；F33 后续

- **目标与入口：** 职位或画像页“找匹配人才”；在授权人才中按当前标准找人，推荐列表不计入已应聘人数。
- **对象与字段：** 目标职位、画像版本、候选人、所用来源版本、逐项匹配、待核实项、其他可证实标签、处理状态；另标“已在本职位流程中”。
- **前提与权限：** 同时有目标岗位权限和候选来源读取权。首个切片只用当前已有授权主档；没有独立分库权限模型时不声称可以搜索全公司储备人才。
- **主要动作：** 选择范围→分析→查看证据→调整本次筛选→加入职位或暂不考虑。筛选不是改正式画像；暂不考虑只影响本岗本版本推荐，可撤销。
- **写入与结果：** 推荐保存必要运行／逐项依据和处理记录，不建假应聘。加入职位复用 H03，并显式选择可向目标流程使用的材料；正式匹配重新建立本次输入关系。
- **交给谁：** 加入成功交目标经办 HR 复核；没有材料授权则交 HR 补充或请求共享，不能将受限材料摘要偷偷带过去。
- **异常与并发：** 已有活跃同岗应聘返回原记录；旧记录已结束才建立下一次。新画像重新计算，旧版暂不考虑不成为永久屏蔽；归档、撤权及来源删除后结果同步限制。
- **验收／代码线索：** 查看十条推荐但不加入时，应聘和排期数量均不变。当前有主档及加入职位基础；有界推荐及独立储备权限仍为设计，不暗含全库语义检索或自动触达。

### H06 面试准备、排期与跟进｜F15–F17/F20

- **目标与入口：** 应聘详情“安排面试”，面试工作区“日程／待安排／待确认／待反馈”。先准备验证目标，再确认时间与参与人。
- **对象与字段：** 应聘、轮次、画像版本、本轮核实项、面试官、主持 HR、时间／时区、地点／会议方式、当前排期版本、邀请结果、每位参与人答复及提纲。
- **前提与权限：** 应聘允许约面、职位允许相应动作，操作者有经办权；面试官有效且能读本场最小资料。外部管理应聘默认跳到飞书排期，不并行约第二场。
- **主要动作：** 从 H04 缺口和 H08 题库选择问题；编辑提纲；检查人员冲突；保存排期；预览后发送邀请；跟踪确认；按最新版本改期、取消、记录未到或完成。
- **写入与结果：** 复用 `Interview / InterviewRevision / InterviewParticipant`；按缺口补 `InterviewGuide / GuideQuestion / InterviewResponse` 及外发记录。排期、通知、答复、面评各有独立真实状态。
- **交给谁：** 邀请交参与人答复；候选人通过 F16 本人验证后的最小事项页确认／拒绝／申请改期，不能因没有完整 App 而由 HR 冒认本人答复。准备页交 I01/I02，结束后交 I03；HR 跟踪失联、改期与催评，主管仅查看瓶颈。
- **异常与并发：** 同时抢占时段只允许合法场次提交；改期取消旧版未发邀请和提醒。部分邀请失败单独重发；旧链接不能确认新时间，发送未知先核对结果。
- **验收／代码线索：** “同意下一轮”仍是待安排；排期保存不显示全部已确认。已有 `interviews.py`、排期版本和参与模型；确认／外发全链、提纲和面评按对应实现验证。

### H07 面评汇总与业务确认｜F14/F18/F19

- **目标与入口：** 应聘详情“面试与评价→提交业务确认”；一次推荐明确要负责人决定什么，避免只有一段含糊的推荐文案。
- **对象与字段：** 本轮已提交面评版本、能力证据、亮点、差距、未核实项、HR 建议、指定决定人、期限、待决定动作及来源快照。
- **前提与权限：** HR 可读所选来源且有应聘经办权；接收人能读完成决定所需材料。仅有草稿不能作为已提交面评；HR 不冒名补交他人的评价。
- **主要动作：** 查看面评收齐情况／催评→检查相互矛盾意见→选择可读正式依据→预览摘要与接收人→提交决定事项；允许撤回尚未处理的旧请求再发新版本。
- **写入与结果：** 沿 06 增量落地 `Feedback / FeedbackRevision / CapabilityEvidence / DecisionRequest / Task`。提交请求不改变最终招聘决定；决定由 B02 处理并与阶段、下一待办同事务保存。
- **交给谁：** B02 同意下一轮交 H06；先联系／待补充交 HR；暂缓有复查人和日期；不推进只结束本次应聘。需测评但未接通时生成待安排，不伪称已测评。
- **异常与并发：** 面评修订后旧请求保留原快照并提示差异；重大依据变化重新发起，不能悄悄替换待审材料。网页和飞书重复点击仅一个最终决定，通知失败不回滚已保存决定。
- **验收／代码线索：** 收齐面评不自动等于通过，业务同意不等于约面成功。当前模型未见完整 `Feedback / DecisionRequest / CapabilityEvidence`；不得以现有 AI 核实记录冒充该段已完成。

### H08 面试题库与岗位提纲｜F17

- **目标与入口：** 保留“面试题库”；HR 可从 AI 初面选择通用问题入库，面试准备时按岗位和验证目的引用，不把每个候选人的私密追问公开共享。
- **对象与字段：** 题干、适用岗位、能力维度、难度、参考观察要点、题目版本、维护状态、来源；本场提纲另外记录具体问题顺序、要求关联及采用时快照。
- **前提与权限：** HR 与招聘负责人维护组织题库均需明确的 `shared_content_manage` 能力及适用范围；面试官可在本场选择已授权模板和编辑个人提纲，不能因参与面试取得组织题库管理权。现有接口较宽的 HR／主管角色授权是待迁移现状，不表示能力授权已落地。
- **主要动作：** 新建／检索／编辑／停用；AI 问题入库前预览并去除姓名、具体雇主、联系方式和个体履历细节；把模板复制为本场问题，再作针对性调整。
- **写入与结果：** 复用 `QuestionTemplate / QuestionTemplateEvent`；本场采用写 `InterviewGuide / GuideQuestion` 及模板版本快照，不通过修改模板改写既有面试。
- **交给谁：** 通用题供其他 HR 及获授权面试官；个体问题留在对应应聘／面试。问题质量反馈交 L03 维护，面评只引用本场实际采用的问题。
- **异常与并发：** 模板删除／停用不抹掉已使用历史；并发编辑检查版本。无法可靠脱敏的问题保留本场，不能依赖只替换姓名即判定安全。
- **验收／代码线索：** 共库看不到候选人个体资料；旧提纲不随模板修改而变化。已有 `question_bank.py` 与版本模型；本场提纲绑定、模板状态和治理按设计补齐。

### H09 企业背书与业务信息核实｜F43

- **目标与入口：** “企业背书→企业详情”，维护企业简介、文化、福利、团队、办公、历程和招聘宣传；在岗位和 AI 初面自动带入关联企业，避免重复输入。
- **对象与字段：** `Enterprise` 名称、行业、简介、内部备注、排序、启用状态；分类背书正文、状态和归属；信息核实问题、指定回复人、答复和处理记录。
- **前提与权限：** HR 与招聘负责人维护企业及背书均需明确的 `shared_content_manage` 能力及适用范围；同组织只是一项前提。现有接口允许 HR／主管维护的较宽授权是待迁移现状，不能声称已经收紧。岗位关联企业必须有效；内部备注不进入 AI，内容管理不授予候选人资料权限。
- **主要动作：** 建企业→维护背书→核对事实→启停／更正；AI 行业与简介建议由 HR 保存；发现不确定信息可提交核实，指定人员回答后由维护者确认是否采用。
- **写入与结果：** 复用 `Enterprise / EnterpriseEndorsement / EnterpriseIssue`；AI 使用时固定企业内容快照。答复与采用分开，答复不自动发布或覆盖正在编辑的企业内容。
- **交给谁：** 对外可使用内容供 H02/H04/H06；未核实事项交指定维护者或业务人；HR 采用更正后后续生成使用新版，历史报告保留当时背景。
- **异常与并发：** 停用／删除企业不进入新 AI 选项；软删除保留内容供授权重归属。企业同名不代表同租户；AI 推测不得冒称已核验事实；背书文本不可执行为模型指令。
- **验收／代码线索：** 企业信息影响介绍与提问上下文，不影响候选人能力事实或得分。已有企业、背书及 `EnterpriseIssue` 代码线索；核实与采用流程须按最新迁移和权限实测。

### H10 结果沉淀与人才再次使用｜F11/F14/F25/F37

- **目标与入口：** 应聘结束后“人才档案→历史与能力证据”；新职位使用已有人员时保留主档，重新判断岗位适配。
- **对象与字段：** 每次应聘的终态、原因、当时岗位标准、正式面评、能力事实与时间、来源权限、联系限制；不保存全公司通用的人才总分或永久不合适标签。
- **前提与权限：** 经办 HR 可结束其负责的本地流程；历史材料复用同时检查来源读取和向目标团队使用的权限。撤权后的旧摘要不能继续复用。
- **主要动作：** 记录本次结束原因；确认／修订／撤回可核实事实；新职位检索→看来源→选择材料→加入新应聘。联系需要另行明确动作及合法渠道，不随加入职位自动发送。
- **写入与结果：** 初筛结束由 `ReviewDecision` 记录，面后业务结束由 `DecisionRequest` 记录，各自与 `Application / StageEvent / Task` 同事务保存；后续实际入职按 F32 单独核验。能力沿 `CapabilityEvidence` 版本；重新加入复用 H03，不复制旧得分或把旧面评标为新面试结果。
- **交给谁：** 新应聘交新岗位 HR；反复出现的标准歧义交岗位 HR 修改下一版。F25 的学习建议后续才增加，HR 采用仍只先形成草稿。
- **异常与并发：** 历史已合档重新授权；同岗活跃应聘不再新建；限制联系人选不能因高匹配而自动触达。清理来源时保留最小历史说明但不留下被删正文副本。
- **验收／代码线索：** 旧职位结束不影响另一职位，新岗从当前画像重新匹配。已有再次加入与应聘历史基础；可复用能力证据、F25 学习和 F37 召回仍分期实施。

- **动作：** 选择时间／部门／职位与计数口径→查看可复核结果→指派改进事项；高级自然语言查询仅转换为受控指标参数，不执行模型生成的任意 SQL。

### A03 飞书、模型与渠道连接｜F23/F08/F09

- **动作：** 按实际授权建立连接→验证身份／权限→用批准测试数据联调→核验读写结果→启用；撤销时停止新任务。消息连接成功不能视为招聘 API 已接通。

- **交接／异常：** 连接恢复交 H03/H06 的实际失败任务重试；未接通保留人工路径或“到飞书处理”。模型只处理批准的最小数据，网页材料里的指令不是系统授权。

### A04 运行异常与受控重试｜F23

- **权限：** 管理员看脱敏错误与操作编号；查看原材料需要另有业务权限。HR 在原业务页看到失败影响和恢复入口，不需要理解技术日志。
- **动作：** 查看原因→核对业务是否已成功→重试指定失败项／暂停连接→移交；未知外发结果先查询外部状态，不能盲目再次发送。
- **写入与结果：** 复用 `ImportItem / ResumeParse / ProfileGeneration` 等运行记录；按模块落实 `AIExecution / InboundDelivery / IntegrationEvent / OutboxDelivery`，不增加任意任务执行器。
- **交接／异常：** 技术恢复不替 HR 做录用决定；重新执行前重查来源版本、权限、当前阶段与幂等键。超过重试上限交管理员或经办人，错误正文不含令牌和完整简历。
- **验收／代码线索：** 重试不重复创建人选／应聘／邀请；原成功项不重做，旧版本任务不能覆盖当前结果。现有导入／解析／画像运行状态可复用，统一异常队列待建设。

### A05 审计、导出与资料治理｜F24/F42

- **目标／入口／字段：** “设置→审计与资料”；记录谁在何时针对何对象做了什么、授权变化、导出字段／范围、清理请求与各对象处理结果。
- **权限：** 审计查看、敏感资料读取、导出、批准／执行清理分别授权；配置管理员不因审计可读而看到简历正文、薪资、模型原始输入或密钥。
- **动作：** 按事件检索；有权者申请导出并预览范围；核实资料更正／清理请求、保留依据与关联影响，再执行明确范围。归档、停用、软删和物理清理分别表述。
- **写入与结果：** 复用 `AuditEvent`；按业务需求落地 `ExportJob / DataRequest / RetentionAction`，遍历文件、解析、报告、证据、索引和缓存；审计只保留最小处理凭据。
- **交接／异常：** 来源权限疑问交业务负责人；外部副本由实际支持的接口／人工程序处理并核验，不声称本地删除已清除飞书。部分失败列清单重试，不误报全部完成。
- **验收／代码线索：** 导出生成和下载均复核当前权限，撤权后旧下载失效；日志没有被清理个人信息残留。已有基础审计与部分导出入口，完整治理规则与期限仍需实际业务确定。

## 5. 面试官事项视图

- **验收／代码线索：** 面试官访问别人的场次或猜 ID 被拒绝；旧邀请不能确认新时间。已有参与者模型，完整事项视图和答复链需实施验收。

### I02 准备本轮问题与核实目标｜F17

- **目标／入口／字段：** 本场“准备面试”；并排显示生效标准快照、HR 关注点、本轮待核实项、引用原文、采用问题及观察要点。
- **权限：** 只读本场允许材料；个人准备草稿按本场角色规则共享，不能自动开放其他职位资料。模板引用不授予维护组织题库的能力。
- **动作：** 选择 H08 通用题、补个体追问、调整顺序；AI 生成建议后人工采用；明确问题验证哪条标准，避免照抄未经核实的 AI 结论。
- **写入与结果：** `InterviewGuide / GuideQuestion` 固定题目与模板／要求／材料版本；不修改公共模板，不把准备记录当面评或已验证事实。
- **交接／异常：** 问题交本人 I03 填反馈；缺关键资料可请求 HR 补充。标准变化提示差异，由经办人确认本场使用版本，不自动重写已经准备的提纲。
- **验收／代码线索：** 同一模板被修改后旧场次保持当时题目，AI 失败仍能手写提纲。题库已有基础，本场提纲关系和面试官准备 UI 仍待接通。

### I03 本人面评提交与修订｜F18/F14

- **目标／入口／字段：** 面试后“提交面评”；每个验证目标填写观察事实、来源说明、结论、未解决问题与下一步建议，草稿保存和正式提交使用不同按钮。
- **权限：** 本人是有效参与者／指定填写者；只签署自己的正式意见。HR 和主管可以催办，不能替本人覆盖评价；多人群面若后续启用须显式指定填写规则。
- **动作：** 保存草稿→检查缺项→提交；后续修订说明原因，生成新版本；无法判断可写未核实，不强迫猜测能力或给假分。
- **写入与结果：** `Feedback / FeedbackRevision / FeedbackItem` 完成本人的面评待办；候选能力证据先成草稿供授权确认。AI 摘要或核实便签不能直接充当签署面评。
- **交接／异常：** 正式反馈交 H07，证据冲突并列保留；未提交草稿默认本人可见。网络失败保持输入，重复提交同版本只有一次；修订不抹去旧业务请求引用的版本。
- **验收／代码线索：** 两名面试官互不覆盖，面试结束但未提交仍显示待反馈；别人不能读草稿。当前未发现完整反馈模型，这是需要补齐的闭环环节。

## 6. 用人负责人事项视图

### B01 岗位问题澄清｜F06

- **目标／入口／字段：** “待我处理→岗位澄清”；显示岗位背景、被问的具体要求、问题、关联草稿版本、提问人、期限及历史答复。
- **权限：** 仅被指定且仍有该职位职责的负责人可回答；读取职位不等于可以答复所有问题。这里只澄清业务含义，不审批 HR 的画像生效。
- **动作：** 回答实际职责与判断依据、说明仍未知的信息；必要时申请 HR 改派。不能修改整个职位或替 HR 将 AI 建议设为必须条件。
- **写入与结果：** 复用 `ProfileClarification`；回答结束本人的任务并产生 HR 整理任务，问题绑定原画像版本。HR 采用、改写并保存使用后标准才变化。
- **交接／异常：** 答复交 H02；草稿已替换、问题撤回或职位关闭后旧问题不能继续生效。原样重试幂等，不同并发答案提示冲突，历史仍可按权限读。
- **验收／代码线索：** 回答不自动清除必须项待核实标记，不新增画像审批。已有澄清模型和网页动作，可复用并收敛为事项视图。

### B02 人选业务决定｜F19

- **目标／入口／字段：** “待我决定”或飞书直达同一事项；显示要决定的下一步、职位／本次应聘、HR 推荐理由、已提交面评版本、证据和待核实内容。
- **权限：** 只允许当前有效的指定决定人；用人负责人角色不等于任意岗位决定权。材料可见性不足时由 HR 调整分享或换人，不能靠消息摘要绕过权限。
- **动作：** 同意下一轮、先联系／补充、建议测评、暂缓或不推进；暂缓填复查日期和责任人，不推进填岗位相关理由；按未实现能力显示真实可执行动作。
- **写入与结果：** `DecisionRequest`、应聘阶段事件和下一 `Task` 同事务；已决定事项只能按显式重新发起流程修正，不直接编辑历史。飞书事件去重与身份映射先校验。
- **交接／异常：** 下一轮交 H06 排期，补充／暂缓交 HR 跟进，结束交 H10；旧卡片、重复点击、撤回、依据变化都返回真实状态。外部主系统的决定仍在原流程执行并核验。
- **验收／代码线索：** 同意下一轮后只出现待安排；网页和飞书不能各自生成一个决定。当前未发现完整 `DecisionRequest` 业务模型，不能将旧画像确认接口挪作面后决定。

### B03 本部门招聘进展｜F21

- **目标／入口／字段：** 精简“本部门招聘”；展示负责岗位、当前需求、有效阶段汇总、等本人处理事项、HR 责任人和更新时间，不复制完整 HR 后台菜单。
- **权限：** 仅明确授权部门／岗位的读取范围；查看进展与查看原简历／其他部门历史／导出为不同能力。兼任面试官时 I01 仍按场次授权。
- **动作：** 查看本部门岗位与待办，下钻相关获准人选，答复澄清、处理 B02 或向经办 HR 提出需跟进的问题；不能拖动阶段替 HR 操作。
- **写入与结果：** 读取同一 `Job / Application / Task / Interview` 的投影；具体决定分别进入 B01/B02，普通浏览不创建另一套汇报记录。
- **交接／异常：** 招聘卡点交岗位 HR 或 L02；无可见数据显示授权范围的空状态。飞书只读资料过期时注明未核验，不能把旧状态标为实时。
- **验收／代码线索：** 和 L01 使用相同口径、不同范围；用人负责人直接调用招聘推进被拒绝。已有 manager 部门角色读取逻辑，精简进度入口仍需实施验证。

## 7. 跨端连通的验收链与后续边界

本文件每个功能的局部验收之外，必须串行检查以下完整场景；它们是计划验收，不是已执行测试。

1. **企业资料到问答：** HR 维护并核实企业背书 → 关联岗位 → AI 初面固定有效企业快照 → 针对岗位与材料给出问题。停用内容不进入新生成，企业宣传不参与人选能力计分。
2. **岗位标准到人岗判断：** HR 起草画像 → 可选 B01 澄清 → HR 保存并使用 → 同一生效版本进入正式匹配；新标准保留旧结果，不需要主管替 HR 批准。
3. **AI 问题到面后决定：** 初面报告指出缺口 → 通用问题经脱敏进入 H08，个体问题进入 H06/I02 → I03 正式提交 → H07 汇总 → B02 决定 → HR 排期或结束，逐步显示真实状态。
4. **在办工作不断人：** HR 离岗 → L02 预览并交接岗位、应聘和未完任务 → A01 停用原账号 → 新 HR 在 H01 接手；旧账号、旧文件链接和旧 AI 请求都不能继续访问。
5. **人才沉淀再使用：** 本次结束 → 有出处的事实保留在授权主档 → 新岗位 H05 推荐 → HR 明确选择材料加入 → 新 Application 与新匹配，不复用旧分数、不自动联系。
6. **飞书与本系统不分叉：** 插件采集到飞书 → 获授权材料参考分析或真实只读读取 → HR 回流程主系统推进 → 有外部回读才显示更新。未连 API 时不展示“已同步”，不以复制本地应聘演示闭环。

F25 画像学习、F27 录音转写、F29/F30 测评与背调、F31/F32 Offer 与入职、F33 语义检索、F34/F35 完整报表、F37 召回及 F38–F41 高级流程维持原分期。本轮补齐它们与角色的交接位置，不因此全部进入首版或预建空表。Offer 接受只进入待入职，实际入职另确认；完整员工管理不进入本方案。

业务仍待明确的项目保持原 Q 清单：编制／Offer 审批、具体接口授权、跨部门共享、保留期限、提醒参数及自动化范围。独立可设计部分继续，未定规则不以默认值冒充已批准。先由 HR 的真实任务验证这套角色设计，再按使用频率决定是否为轻协作身份增加常驻菜单。
