## 2. 先掌握整条业务链

**招聘需求 → 职位、画像与流程 → 官网／内推／猎头／第三方广告 → 简历收取或插件主动导入 → 查重与人才档案 → 加入职位形成投递 → 评估、笔试、面试 → Offer → 待入职与实际入职 → 人才库复用和报表。**

- 招聘需求是计划；职位是招聘任务；广告是渠道入口。一个职位可以发布多个广告。
- 人才是长期主档；简历是资料及其版本；投递是某个人针对某个职位的应聘记录。统计时先说明算人、投递、场次还是操作次数。
- “加入其他职位”保留原投递并建立另一条；“转移职位”会终止原投递。同一人才、同一职位不能同时有两条活跃投递，结束后可重新创建。
- 管理员配置规则，HR 组织与推进，员工执行评估／面试／审批，候选人反馈意愿，内推与猎头提供有归属的人选。承担一项任务不等于得到全库权限。
- 通知已发、对方已确认、面试已完成、面评已提交是不同事实；接受 Offer 不等于入职；内推奖励记为已发放不代表系统完成转账。
- 简历缺字段、职位匹配失败、疑似重复、邀约未答复、通知失败、待面评应分别进入相应待处理路径，保留处理责任。

上述关系主要依据下面的 HR、管理员、员工手册及 FAQ；不是所有企业都固定采用同一流程。

## 3. 入门手册：7 篇必须逐项覆盖

### 3.1 [快速上手飞书招聘](https://www.feishu.cn/hc/zh-CN/articles/566584729896)

了解产品定位、六种角色手册和主要进阶入口。这是导航，不能代替各角色的权限、操作及异常规则；正文未完整列出的群面手册仍须补读。

### 3.2 [飞书招聘员工入门手册](https://www.feishu.cn/hc/zh-CN/articles/856890248633)

员工通过首页任务、机器人、日历参与简历评估、阅卷、面试、Offer 审批和内推；成为用人经理后可查看相关职位与候选人。入口和数据范围由角色及任务决定。
掌握背靠背评估、原始附件与标准简历、面试空间与助手、自助约面、面评提交及下一轮交接。群面共同笔记与指定人提交的正式面评不同。
内推可代投或分享带归属的链接；Offer 审批人与内推人承担不同职责。查看、下载、导出和敏感字段权限不能混同。

### 3.3 [飞书招聘管理员入门手册](https://www.feishu.cn/hc/zh-CN/articles/731255043228)

企业超级管理员与招聘管理员职责不同；管理员配置席位、角色、数据范围、字段、流程阶段与可用动作、登记表、面评表、题库、消息及自动化。
重点阅读投递锁定、内推／猎头保护期和企业自有简历保护：锁定约束并行推进，保护期处理归属，不能相互代替。
掌握官网、渠道账号与邮箱、猎头合作、人才分库、隐私与保留、Offer 审批及敏感信息配置；某些修改会重走审批。
API 管理职位／需求、三方协议及人事对接会改变可编辑入口；人事接管入职等事件后，招聘侧可能不能手工修改。接入开关不是对接成功证据。

### 3.4 [飞书招聘 HR 入门手册](https://www.feishu.cn/hc/zh-CN/articles/381040174542)

贯穿工作台待办、建岗与画像、发布广告、渠道接收、招聘助手、查重入库、筛选评估、笔面试、Offer／背调／入职、人才库和报表。
待分配池区分外部职位未匹配、缺职位信息、缺简历必填项；分别匹配职位、人工选岗或补资料，不能把收到文件当作已正确投递。
人才主档保留多份附件与标准简历，上传资料与更新标准简历是可区分的动作；转阶段、转职位、另加职位、分享、解锁各有不同结果。
自助约面先给可选时间，预约成功才形成确定场次；改期、取消、未到场、催评、帮写面评属于具体面试。Offer 接受进入待入职，实际到岗另确认。
人才库支持检索、关注、文件夹、共享、意向更新和按职位画像推荐；人才盘点到多维表格在该手册中为单向同步，表格编辑不回传。

### 3.5 [飞书招聘校招 HR 入门手册](https://www.feishu.cn/hc/zh-CN/articles/944601311055)

在通用流程上掌握校招项目、投递次数、志愿、意向城市与调剂、按项目锁定、宣讲会签到、批量笔试及面试。签到记录不等于职位投递。
试卷使用与编辑权限分开；作答窗口与阅卷截止用途不同，阅卷截止主要用于提醒。拒绝笔试邀请不等于考试不通过。
集中多轮与集体群面分别组织；三方协议如采用 API 同步，不能假定仍可手工维护。跨规则冲突优先级需按企业配置核验。

### 3.6 [飞书招聘内推运营专员入门手册](https://www.feishu.cn/hc/zh-CN/articles/428171330321)

掌握员工代投／分享投递、推荐归属、入职转正奖、流程进展奖、活动奖与开源奖，以及规则适用范围和命中优先级。
奖励从待确认到待发放，再由企业实际付款并标记已发放；核算、调整金额、取消和重新确认均有不同动作权限。
专项手册区分同类规则取最新与活动可叠加，不能把所有奖励直接相加。人事日期的同步或人工维护会影响计奖。

### 3.7 [飞书招聘猎头供应商入门手册](https://www.feishu.cn/hc/zh-CN/articles/903264730647)

企业邀请并与供应商飞书团队建立合作后，应用管理员、某企业猎头管理员、顾问分别管理不同范围；供应商使用猎头平台，不是进入企业 HR 后台。
顾问按获派职位推荐简历、推荐报告，查重并跟进；是否需接收确认、是否显示联系方式或允许改资料由招聘方配置。
停用保留历史但失去权限；有在跟进候选人时不能直接移除顾问，招聘方禁用不能由供应商自行解除。过期邀请由企业重发。

## 4. 进阶功能：8 篇必须逐项覆盖

### 4.1 [飞书招聘进阶功能介绍](https://www.feishu.cn/hc/zh-CN/articles/371978295578)

导航至笔试、集中面试、虚拟职位与报表。概览中有“集中／集体”混写，业务含义以各自专项手册为准，不能由导航一句话推断完整行为。

### 4.2 [管理员及 HR 笔试操作手册](https://www.feishu.cn/hc/zh-CN/articles/070150189240)

管理员准备测试阶段、流程、供应商账号、试卷和通知；HR 在允许阶段单人或批量安排，候选人答复／作答后由阅卷人看报告、给成绩和结论。
区分发送状态、邀请答复、作答、阅卷；拒绝会取消该次考试。供应商不回传成绩时需人工处理，不能承诺所有供应商同样回传。
未作答时可调整的事项与已作答后不同；阅卷截止是催办节点。试卷查重避免重复邀请，分数与招聘推进规则分开配置和核验。

### 4.3 [HR 集中面试操作手册](https://www.feishu.cn/hc/zh-CN/articles/093074753888)

同日同地点集中完成多轮面试：HR 建活动、纳入对应流程的职位、候选人、预约容量和面试官，再通知、预约、签到、排队派单。
状态包括待安排、等待面试、面试中、待确认结果、完成本场、结束面试；结束当天安排不等于终止整个应聘。
面评后 HR 决定下一轮；显式开启时可自动派单和按结果流转。临时加人需满足本场投递前提，活动备注不会自动成为档案备注。
注意通知失败重发、未预约、超时未面完、转到活动外职位等例外；专门手册说 HR 暂不能编辑集中面试面评，须由对应面试官修改。

### 4.4 [面试官集中面试操作手册](https://www.feishu.cn/hc/zh-CN/articles/503182504730)

面试官答复日程后仍要到活动签到，才能被派单；接单看资料、执行面试、提交面评，再选择继续或暂停接单，离场时签退。
接受日程、签到、休息、签退是不同事实。面试空间和助手结合员工手册阅读；文档未完整规定断网恢复或补位算法。

### 4.5 [虚拟职位操作手册（管理员及 HR）](https://www.feishu.cn/hc/zh-CN/articles/434091718316)

用于统一对外招人后分配城市、门店或部门；管理员先开放权限与流程动作，虚拟职位和关联实体职位须使用相同招聘流程。
可先评估、笔试和面试，沟通 Offer 前必须落实到实体职位；分配带入阶段和已有笔面试记录，也可回退来源虚拟职位。
支持批量分配、自动分配与自动回收；意向城市约束地点。平均、比例和动态分配不是同一规则，未公开的动态算法不能解释为智能画像匹配。

### 4.6 [自定义报表功能操作手册](https://www.feishu.cn/hc/zh-CN/articles/443610896847)

先选招聘操作、招聘进度、职位、人才或面试满意度等数据集，再定分组、计数／去重／时长／比例、过滤和图表；切数据集会使原配置失效。
编辑保存、发布报表、分享、发布仪表盘分别完成；仪表盘统一筛选要映射到各报表字段，不能假定自动覆盖全部图。
普通数据可见范围、共享分享人数据权限、允许导出是不同授权。报表下钻和导出须保持统计口径；删除报表与删除分组影响不同。
旧手册和更新日志的导出上限有差异，不能固定承诺某个行数。多人群面评价统计的旧限制也会影响工作量解释。

### 4.7 [面试官集体面试操作手册](https://www.feishu.cn/hc/zh-CN/articles/619799382646)

集体面试即群面，多名候选人同场；面试官可共同记笔记，每位候选人的正式面评由指定填写人负责，不要求每名面试官各交一份。
场次面板可对照人员和评价状态；云文档共同笔记不等于正式结论。该手册提醒普通面试官可能被旧报表误计为未评价，需核验当前行为。

### 4.8 [HR 集体面试操作手册](https://www.feishu.cn/hc/zh-CN/articles/035260218559)

HR 批量安排同场人选、统一轮次、面试官及指定填写人；跨职位组织须有共同轮次。该手册记载每场最多 30 人，当前限额待租户核验。
改期或修改可能影响整场，须覆盖全部相关职位权限；已有评价、候选人被其他职位锁定会限制操作。整场取消与单人取消不同。
催评面向指定填写人；HR 在候选人详情帮写／编辑的权限，不等于可从面试官面板代填整场。不能把集中面试的规则直接套到群面。

## 5. 飞书招聘助手：功能、平台衔接与边界

官方入口：[HR 手册的插件章节](https://www.feishu.cn/hc/zh-CN/articles/381040174542)、[效率课程第三课](https://www.feishu.cn/hc/zh-CN/academy/quick_guide_to_FeishuHire#0_2)、[常见问题](https://www.feishu.cn/hc/zh-CN/articles/355896296441)。

| 功能 | 已确认的使用链路与结果 |
|---|---|
| 安装与启动 | 从招聘首页插件入口安装，在浏览器内使用；飞书客户端工作台不能运行此扩展。官方历史教程展示 Chrome／360，不当作当前完整兼容矩阵 |
| 当前简历识别 | HR 在第三方网站打开简历并启动助手，插件识别当前页面，HR 核对姓名、电话、邮箱等基本资料 |
| 相似／重复提示 | 呈现库中疑似人才及查看入口，先检查身份再决定处理；不是看到相似提示就能确定同一个人 |
| 新建人才 | 检查资料后保存简历入飞书招聘，并可进入人才详情核对结果 |
| 更新已有人才 | 教学演示可更新库中人才的标准简历，避免反复新建；具体字段覆盖策略需当前版本验证 |
| 人工纠正识别 | 教学界面提供“识别有误，新建人才”入口；不据此声称可绕过所有平台查重约束 |
| 关联与跟进 | 保存前可选择职位、人才文件夹、关注；加入职位形成投递，单纯入库不等于已安排招聘任务 |
| 跳转平台 | 打开已有或新建人才详情，继续处理档案和投递；平台承担后续评估、面试及权限管理 |
| 辅助发岗 | 从飞书职位渠道发起，登录第三方站点，进入发布页并填充信息；HR 补齐字段并提交 |

平台手册的精准查重使用手机号或邮箱相同，模糊查重参考工作／教育经历；疑似合并与取消标记是平台能力，未确认插件内直接合并。
渠道邮箱收取投递与插件主动采集是两条入口；职位映射、接收邮箱和账号配置影响自动分配。未匹配或缺字段需到待分配池处理。
飞书里改职位不会自动更新第三方已发布广告；广告刷新也不等于更新内容。不要承诺插件持续双向同步全部渠道。
隐藏或虚拟联系方式需 HR 依渠道规则沟通补充；安装后仍提示未安装时先确认是否在装有扩展的浏览器操作。
尚未确认当前插件版本、完整网站／页面兼容清单、批量采集能力、独立约面能力、扩展权限清单及字段覆盖细则；不得把历史课程中的网站演示推广为所有网站可用。

## 6. 职位画像：不得误说飞书没有人才画像相关能力

来源：[HR 手册创建职位及 10.2 人才推荐](https://www.feishu.cn/hc/zh-CN/articles/381040174542)、[新版职位画像详解](https://bytedance.feishu.cn/docx/WLF8d2IbYoUfcyxQBqucg5kVnQh)、[更新日志 2023.04 条目](https://www.feishu.cn/hc/zh-CN/articles/726329177535)。

- 建职位时可开启职位画像与标签偏好；人才库的“人才推荐”也可设置画像，用于寻找符合标准的人才。
- 条件涵盖工作经历、教育经历、技能、项目；公开截图按工作经历、教育经历、技能／项目三组呈现。
- 标签可新增、删除，并设置加分、必备、排除。标签含义与命中依据要结合职位和候选人查看。
- 候选人展示总体与分项匹配星级、命中标签和其他标签，可回看职位画像；画像匹配是招聘评估的参考。
- 详解记载管理员在智能化设置开启画像生成，文档中默认关闭；复制职位可抽取标签，编辑职位信息可重算标签。
- 公开资料未给出星级算法、准确率、权重、推荐阈值或画像读写 API，也未证明“必备／排除”会自动淘汰，不得补造。
- 详解来自历史更新日志；本次读了匿名公开正文和 HR 手册关键截图，受限图片未绕过权限，未据此断言企业已启用。

本项目对应设计见 [11 飞书职位画像对照与闭环设计](../产品设计/11_飞书职位画像对照与人才画像闭环设计.md) 和 [10 人才画像方案](../产品设计/10_人才画像设计与闭环方案.md)。岗位画像、人才证据、推荐记录、正式应聘应分开。
**本项目已确定：有职位操作权限的 HR 用 AI 起草、修改后直接“保存并使用”，不另交用人负责人审批。** 保留版本、权限和待核实必须项校验；AI 不自动启用。面后业务确认等其他审批仍照原规则。

## 7. 与本项目衔接时的固定边界

现有可确认链路是“招聘网站 → 飞书招聘助手 → 飞书人才库／投递”，不能画成插件已经直连本项目。飞书登录、消息授权和招聘业务数据接口授权不是一回事。
未经用户决定，不默认替换飞书，也不为飞书在途应聘创建另一条可独立推进的本地流程。每条应聘要明确唯一的阶段事实来源。
手动授权导入、只读接口、可写集成及迁移分别设计；手动材料标来源和时间，接口成功须有结果核验，失败／未知结果保留重试与核对路径。
同名人选或同名职位不能自动合并／映射；复用人才仍须检查材料权限。不得通过摘要、标签、报表或 AI 输入绕过来源访问范围。
平台已经存在的能力先比较差距再设计，不因本文件内容自动扩大本项目开发范围。实现状态以代码、运行和验收证据为准。
