# 知遇 AI 招聘工作台

当前已能完成：HR 登录、创建职位、保存招人要求、提交负责人确认、要求补充、开始招聘、暂停／关闭／重新开启，以及查看版本和操作记录。首页待办与后端操作同步更新，刷新不会丢失已保存的数据。

职位详情的“澄清问答”可针对草稿中的一条要求向指定负责人提问。负责人从首页待办直达问答；答复后 HR 收到整理待办，核对并保存新版本后再提交正式确认。历史问答绑定原版本，回答不代表批准画像。问题和答案提交失败后保留输入，切换标签或关闭前提示尚未保存内容。

原 Ant Design Pro 模板和模拟接口已经移除。当前使用 React 19、TypeScript、Vite、Tailwind CSS、shadcn/ui 与 Semi Design；锁定版本见 `package.json` 和 `package-lock.json`。保留原模板 MIT 许可证用于历史溯源。

## 本地启动

先按 [后端说明](../api/README.md) 启动独立 PostgreSQL 和 Django，再在本目录使用 Node **24.21.0**：

```sh
npm ci
npm run dev
```

工作台地址：`http://localhost:5174/`。开发服务只监听本机。默认通过同源 `/api` 转发到 `127.0.0.1:8100`，需要其他后端地址时使用 `API_TARGET` 环境变量。用户的外部首页端口和文件不受影响。

登录入口统一在公共首页 `http://localhost:5173/`，点击“开始体验”或“开启知遇之旅”进行飞书登录；工作台不再提供账号密码登录页。未登录直接访问工作台、会话过期后刷新以及成功退出，均返回后端 `PUBLIC_HOME_URL` 指定的公共首页。本地默认是 5173，正式部署必须填写正式首页地址。

右上角显示本次飞书登录返回的姓名、头像和后端已授权角色；头像缺失或加载失败时显示姓名首字。旧会话需重新从首页进行一次飞书登录以更新资料。仅本地测试会话显示“本地体验”，不会冒用与测试账号绑定的飞书资料。

本机虚构账号由后端 `seed_local` 创建，仍可用于受控开发和自动验收，通过后端真实会话校验权限；不再展示账号密码表单，也不能切换前端角色绕过权限。密码和体验资料不提交到 Git。

## 验证

```sh
npm run lint
npm run typecheck
npm run build
npm test
```

首次使用 Playwright 时，安装对应 Chromium：`npx playwright install chromium`。默认从 `~/.local/bin/uv` 启动后端，也可设置 `UV_BIN`。`npm test` 读取 `apps/api/.env` 中本机数据库连接，仅重建 **recruitment_e2e**，不修改本地工作库 `recruitment`；要求连接角色能创建数据库。验收使用 5175（工作台）、5176（公共首页）和 8101（后端），不占用日常预览端口。需先安装 `apps/web` 的依赖。

已保存的浏览器验收涵盖建岗到确认、刷新持久化与旧版本、真实筛选、请求失败保留输入并重试、窄屏详情、权限隔离、退出登录。新增导入与复核浏览器回归覆盖部分提取失败、身份确认响应丢失、同名分开、同岗再应聘及版本冲突保留输入。后端另验组织关联、状态前置条件、版本冲突、并发、文件权限和登录安全。

## 当前边界

已交付建岗确认与 D02 的导入／人工复核增量，不代表整个 D02 或 P0 完成。候选人入口支持受控 PDF/DOCX 导入、实际文字提取、失败后人工摘录、疑似重复核对、多次独立应聘、人工复核与待办直达。飞书网页登录已接入；面试与候选人确认、能力证据复用、招聘 AI、飞书招聘通知及日历同步、渠道发布和回传仍待后续实现。当前没有成员授权配置页面，实际团队账号与角色需由维护人员配置。

候选人库的“新增候选人”支持在同一个表单上传、核对和保存。文字型 PDF、DOCX、TXT 可提取文字并回填明确字段；图片和旧版 DOC 仅保存附件，识别失败可继续人工填写。每份附件不超过 10MB。保存后返回按人才主档展示的列表，显示城市、学历、工作年限、期望薪资和来源，详情可回看材料及多次应聘。

职位和来源可以暂不选择；未关联职位时只保存本人的候选人主档，不创建应聘或待办。之后可从人才画像选择该人加入职位。主档与附件仍按当前 HR、职位及原件下载权限提供；失败重试不重复创建记录。相关验收见 `candidate-library.spec.ts`、`resume-fields.spec.ts` 和后端 `test_candidate_library.py`。

`npm run preview` 仅提供构建后的静态页面；正式部署需要将网页和 `/api/` 配到同一 HTTPS 站点，不能用静态预览代替完整后端。开发服务器不是生产部署方案。
